# DopaDrop: правила разработки

- Основная спецификация — `CODEX_SPEC_DOPADROP.md`; фактический прогресс — `PROGRESS.md`.
- Архитектура — модульный Flask-монолит, Jinja2/vanilla JS, SQLite, статический JSON.
- Перед изменениями изучать существующий код. Не переписывать работающие компоненты без причины.
- После изменений запускать соответствующие тесты; обновлять журнал прогресса.
- Не объявлять непроверенные функции работающими.
- Не удалять пользовательские данные; тесты используют отдельную временную БД.
- Не публиковать проект и не выполнять push без разрешения.
