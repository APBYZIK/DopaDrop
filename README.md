# DopaDrop

Магазин совершенно необязательных вещей: 15 шуточных товаров, корзина, фиктивное оформление, чек, QR и автоматическое пятиминутное приключение заказа.

**Никакой настоящей оплаты или доставки.** Приложение не запрашивает имя, адрес, телефон, email или банковские данные. Цены в рублях используются только для игры; чек не имеет юридической силы.

## Быстрый старт

Нужен Python **3.12+** с pip и venv. Реально проверено на **Python 3.14.0, Windows, Microsoft Edge (headless)**. Команды Linux/macOS приведены ниже; отдельный запуск на этих ОС не выполнялся. Зависимости и транзитивные версии закреплены в requirements.txt.

Windows PowerShell, из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m flask --app run.py init-db
.\.venv\Scripts\python.exe -m flask --app run.py run --debug
```

Откройте **http://localhost:5000**. Если окружение уже создано и зависимости установлены, достаточно двух последних команд. При использовании интерпретатора из PyCharm убедитесь, что выбран Python из проектной .venv.

Также можно открыть run.py в PyCharm и нажать **Run** либо выполнить `.\.venv\Scripts\python.exe run.py`. Прямой запуск поднимает локальный сервер на http://127.0.0.1:5000 без отладчика. База должна быть предварительно создана через init-db (в текущем проекте это уже сделано). Не запускайте два сервера одновременно на одном порту; остановка в PyCharm — кнопкой Stop.

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m flask --app run.py init-db
python -m flask --app run.py run --debug
```

Активация в PowerShell необязательна; при желании используйте `.\.venv\Scripts\Activate.ps1`. Для запуска не требуется Node, npm, CDN или внешний API. После установки зависимостей приложение работает без интернета.

## Конфигурация и база

| Переменная | Значение по умолчанию / назначение |
|---|---|
| PUBLIC_BASE_URL | http://localhost:5000 — канонический корень ссылок в QR и для копирования; только схема + домен + необязательный порт |
| DATABASE_URL | sqlite:///shop.db — файл **instance/shop.db**, относительно Flask instance directory, а не текущего каталога терминала |
| SECRET_KEY | Локальный fallback с предупреждением; для production задайте собственное случайное значение |
| DOPADROP_ENV | production включает обязательный SECRET_KEY и HTTPS в PUBLIC_BASE_URL |
| FLASK_DEBUG | 1 в примере .env; перед публикацией отключить |

`run.py` загружает .env перед импортом конфигурации. В тестах можно передать `create_app(config_overrides)`, включая CATALOG_PATH, TRACKING_SCENARIOS_PATH, CLOCK и TOKEN_GENERATOR.

`init-db` создаёт отсутствующие таблицы через SQLAlchemy; **не удаляет заказы**. Без этой команды каталог доступен, но операции с заказами требуют таблиц. SQLite использует foreign_keys=ON и busy_timeout=5000 ms. В Python даты timezone-aware UTC; тип UTCDateTime сохраняет naive UTC в SQLite и восстанавливает tzinfo при чтении.

Обычная БД и .env исключены из Git. Не удаляйте instance/shop.db для «обновления схемы» — это уничтожит историю. Для экспериментов назначьте отдельный DATABASE_URL, например sqlite:///scratch.db. Сбрасывать можно только заведомо одноразовую тестовую базу после остановки работающего с ней сервера. Автотесты сами создают и удаляют свои временные базы.

Для демонстрации QR на телефоне:

1. Задайте PUBLIC_BASE_URL=http://<локальный-IP-компьютера>:5000 в .env.
2. Запустите `python -m flask --app run.py run --host 0.0.0.0 --no-debugger --no-reload`, предварительно отключив FLASK_DEBUG.
3. Подключите телефон к той же сети, обеспечьте разрешённый сетевой доступ и откройте QR.

localhost в QR указывает на устройство, которое его сканирует. Само приложение не меняет сетевые настройки и не публикуется автоматически.

## Архитектура

Один модульный Flask-монолит. Flask 3, Jinja2, vanilla JS/CSS, Flask-SQLAlchemy 3 / SQLAlchemy 2, SQLite, qrcode/Pillow, pytest. Нет фоновых работников и отдельного frontend-сервера.

```text
Browser: Jinja + CSS + JS + localStorage
                     |
              HTML / JSON Blueprints
                     |
    Catalog -> Cart -> Order       Tracking / Receipt / QR
       |                 |                 |
 catalog.json     OrderRepository       снимок заказа
                         |
                  SQLAlchemy -> SQLite
```

```text
app/
  __init__.py                app factory, сборка сервисов, CLI, заголовки
  config.py / extensions.py  настройки и SQLAlchemy
  errors.py                  ошибки домена и HTML/JSON-маппинг
  data/                      catalog.json, tracking_scenarios.json
  models/                    неизменяемые DTO, Order, OrderItem, UTCDateTime
  repositories/              доступ к заказам через ORM
  services/                  Catalog, Cart, Order, Receipt, QRCode, Tracking
  routes/                    pages, orders_api, qr, HTTP-сериализация
  templates/                 страницы и компоненты Jinja
  static/css/                адаптивный интерфейс и печать чека
  static/js/                 API, корзина, checkout, каталог, трекинг, чек
tests/                       изолированные pytest-проверки
scripts/browser_check.py     необязательные проверки настоящим браузером
instance/                    локальная БД (не коммитить)
artifacts/                   локальные QA-отчёты, скриншоты и кэш (не коммитить)
```

Статические сервисы собираются в app.extensions['dopadrop']; OrderService и OrderRepository создаются в актуальном app/request context. Сервис заказа управляет commit/rollback. Routes не выполняют SQL. Сервисы не используют request/session/render_template. Весь заказ и позиции сохраняются атомарно.

## Страницы и API

| Метод и URL | Назначение |
|---|---|
| GET / | Каталог; параметры category и q фильтруют серверные карточки |
| GET /cart | Корзина из localStorage |
| GET /checkout | Резюме и обязательный checkbox о фиктивности |
| GET /orders/<token>/success | Чек, QR, копирование ссылки, печать |
| GET /track/<token> | Серверный статус и автоматически обновляемый таймлайн |
| GET /orders/<token>/qr.png | PNG в памяти, кодирует PUBLIC_BASE_URL + /track/<token> |
| GET /api/catalog | {categories: [...], products: [...]} со всеми полями Product |
| POST /api/orders | Создать заказ или вернуть существующий по UUIDv4 |
| GET /api/orders/<token>/tracking | Номер, server_time, created_at и tracking |

Пример POST для Bash; в PowerShell используйте curl.exe и файл тела через --data-binary @request.json:

```bash
curl -X POST http://localhost:5000/api/orders \
  -H 'Content-Type: application/json' \
  --data '{"idempotency_key":"d35833cb-9d5d-4c18-8b90-399837ed57a2","items":[{"product_id":"invisible-socks","quantity":2},{"product_id":"tomorrow-planner","quantity":1}]}'
```

Этот пример создаёт 2 позиции / 3 единицы на **189700 коп. = 1 897,00 ₽**. Для нового заказа используйте новый UUIDv4; повтор того же примера вернёт существующий заказ.

Успех: 201 для нового заказа, 200 для идентичного повтора:

```json
{
  "order": {
    "order_number": "DD-20261115-A7D9F2",
    "public_token": "<криптостойкий токен>",
    "created_at": "2026-11-15T12:00:00Z",
    "total_kopeks": 189700,
    "item_count": 3,
    "items": [
      {"product_id":"invisible-socks","product_name":"Невидимые носки","quantity":2,"unit_price_kopeks":49900,"line_total_kopeks":99800},
      {"product_id":"tomorrow-planner","product_name":"Планер «Начну завтра»","quantity":1,"unit_price_kopeks":89900,"line_total_kopeks":89900}
    ]
  },
  "links": {
    "success": "/orders/<token>/success",
    "tracking": "/track/<token>",
    "qr": "/orders/<token>/qr.png"
  }
}
```

Тело принимает **только** idempotency_key и items; строка items — только product_id и quantity. Никаких клиентских цен, сумм или персональных данных. UUIDv4 нормализуется; SHA-256 вычисляется по отсортированным ID/количествам. Повтор ключа с другой корзиной — 409. Уникальные индексы защищают и при конкурирующих запросах.

Ошибки имеют форму:

```json
{"error":{"code":"invalid_quantity","message":"Количество товара должно быть целым числом от 1 до 10.","details":{"index":0}}}
```

400 — некорректный JSON; 415 — Content-Type; 413 — тело более 16 КиБ; 422 — валидация; 409 — конфликт попытки; 404 — неизвестный токен; 500 — внутренняя ошибка без подробностей в ответе.

Ответ tracking содержит current_stage_index, current_stage_id, elapsed_seconds, is_final, next_stage_at и stages. В каждом этапе есть id, title, description, emoji, start_after_seconds и state (complete/current/pending). Время — ISO 8601 UTC с Z; после финала next_stage_at равен null.

## Корзина и история

Ключ localStorage — dopadrop.cart.v1, формат:

```json
{"version":1,"items":[{"product_id":"invisible-socks","quantity":2}]}
```

Названия и цены для интерфейса приходят из API каталога. Сервер независимо проверяет всё заново. Лимиты: 1–15 разных товаров, 1–10 единиц каждой позиции, максимум 50 единиц; bool/float/строки вместо целого количества отклоняются. Повторяющиеся ID в POST запрещены.

Корзина синхронизируется между вкладками через storage event. Повреждённые данные сбрасываются с сообщением, неизвестные товары удаляются, при запрете localStorage используется память текущей страницы. В этом режиме переход/перезагрузка теряет корзину — интерфейс предупреждает об ограничении.

Checkout сохраняет ключ и снимок запроса в sessionStorage (dopadrop.checkout.v1). Сетевой повтор использует тот же payload; при изменении корзины создаётся новый ключ. При недоступном sessionStorage повтор возможен в памяти текущей страницы; перезагружать её после неопределённого результата не рекомендуется. После успеха корзина очищается и открывается чек; ссылка также показывается как резервный способ перехода.

Заказ хранит собственные названия и цены позиций. Редактирование каталога не меняет ранее созданные чеки. Публичный доступ — только по 192-битному случайному токену secrets.token_urlsafe(24), а не по внутреннему числовому ID. Владение ссылкой даёт доступ к фиктивному заказу.

## Автоматический трекинг

| После создания | Этап |
|---|---|
| 0 секунд | Заказ принят. Мы морально готовимся. |
| 30 секунд | Упаковываем в воображаемую коробку. |
| 90 секунд | Курьер вышел. Кажется, не туда. |
| 180 секунд | Заказ застрял в мультивселенной. |
| 300 секунд | Доставлено прямо в ваше воображение. |

На каждом запросе сервер считает max(0, floor(now_UTC − created_at_UTC)) и выбирает последний достигнутый порог из сохранённой версии сценария. На точной границе уже действует новый этап; финальный остаётся навсегда. Статус не записывается в БД, никаких cron/Celery/потоков трекинга нет. Перезапуск сервера и другое устройство не меняют результат.

JS опрашивает сервер каждые 5 секунд, останавливается на скрытой вкладке, сразу обновляется при возвращении и завершает polling после финала. Сетевая ошибка сохраняет последний известный статус с сообщением о повторе. Без JS первоначальное состояние уже есть в HTML. Countdown не реализован — это необязательное улучшение.

## Редактирование данных

Каталог загружается один раз при создании приложения и проверяется: ровно 15 товаров, 5 категорий, по 3 в каждой, уникальные kebab-case ID, корректные поля и целые цены. После правки app/data/catalog.json перезапустите сервер. Не редактируйте JSON одновременно с работающим процессом, ожидая мгновенного обновления.

Сценарии тоже валидируются при старте. **Не меняйте default-v1 после создания заказов**, включая тексты и интервалы: старые заказы ссылаются на него. Для будущего развития добавляйте новый ID/версию, сохраняйте старые определения и явно назначайте новую версию новым заказам в OrderService. В MVP используется только default-v1, version=1.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

На Linux/macOS с активным окружением: python -m pytest -q. Тесты используют tmp_path SQLite и управляемый UTC-clock; реальная instance/shop.db не затрагивается. Проверяются каталог, корзина, модели/ограничения, транзакции, rollback, коллизии, повторные запросы, API, снимки, QR, страницы, заголовки и все временные границы без sleep.

Финальный результат: **93 passed**, pip check без конфликтов. Чистая установка проверена в .venv-verify с локальным кэшем подлинных PyPI wheels, затем проверены CLI и HTTP-запуск. В этой среде pip через SOCKS-прокси зависал; для повторной установки на той же платформе доступна команда python -m pip install --no-index --find-links artifacts/wheels -r requirements.txt. Кэш не заменяет обычную установку на других платформах.

Необязательная проверка настоящим браузером:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
.\.venv\Scripts\python.exe scripts/browser_check.py
```

Скрипт использует установленный Edge по стандартному Windows-пути. Если его нет, сначала выполните python -m playwright install chromium. Это QA-инструмент, не зависимость веб-приложения и не Node toolchain. Скрипт поднимает собственный тестовый сервер на 127.0.0.1:5010 и временную БД, управляет временем браузера и сервера, сохраняет отчёт и скриншоты в artifacts/. Порт 5010 должен быть свободен.

Проверены: полный путь покупки, потеря ответа после commit и повтор после reload, двойной клик, две вкладки, испорченный/запрещённый storage, пустая корзина, таймлайн, остановка polling на финале и событии скрытия, ширины 320/375/768/1280. В browser_check событие видимости моделируется программно; реальное переключение нативных вкладок остаётся в ручном чеклисте.

Ручной чеклист:

- Добавить носки ×2 и планер ×1; увидеть 1 897,00 ₽, изменить количество, удалить, вернуть товар.
- Перезагрузить корзину; открыть вторую вкладку и проверить синхронизацию.
- Принять условие о фиктивности, дважды нажать оформление; обновить чек.
- Отключить сеть при POST, затем восстановить и повторить без изменения корзины.
- Перейти по ссылке и отсканировать QR телефоном с корректным PUBLIC_BASE_URL.
- Дождаться 30/90/180/300 секунд; скрыть вкладку и вернуться; перезапустить Flask.
- Проверить клавиатурную навигацию, копирование ссылки и печать, ширины от 320 px.

## Ограничения и публикация

- MVP локальный: нет авторизации, админки, личного кабинета, email, реальных платежей, остатков или доставки.
- Неизменяемость старых сценариев поддерживается дисциплиной версионирования файла; встроенной системы миграций/архива сценариев нет.
- SQLite рассчитана на небольшой объём. Перед открытой публикацией нужны резервные копии, полноценный WSGI-сервер, HTTPS, корректный PUBLIC_BASE_URL, секрет окружения, выключенный debug и rate limiting на reverse proxy.
- Rate limiting в MVP отсутствует. Не открывайте Flask dev-server в интернет. Настройте access logs так, чтобы публичные токены не попадали в сторонние системы журналирования.
- CORS не открыт, принимается только application/json. Cookie-аутентификации нет; при добавлении аккаунтов понадобится полноценная CSRF-защита.
- no-store/noindex/no-referrer установлены для заказов, QR и трекинга; нет аналитики, внешних шрифтов и CDN. QR не зависит от недоверенного Host.
- Чек — только HTML/печать браузера. QR проверен по PNG и переданному URL; физическое сканирование камерой телефона не выполнялось.
- Обычный CUA browser/native host в среде разработки недоступен; браузерные проверки выполнены отдельным headless Edge.
- Коммиты не создавались: исходная рабочая директория не была Git-репозиторием. Публикация и push не выполнялись.

Фактические результаты и дальнейшее состояние — в PROGRESS.md. Исходные требования — CODEX_SPEC_DOPADROP.md.
